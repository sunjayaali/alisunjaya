## Learning About Flutter BLoC

When I first started building Flutter apps, I mostly used `setState` to manage state. For simple screens, it worked pretty well.

For example, when loading a user, I could just keep the loading state and user data inside the widget:

```dart
bool isLoading = false;
User? user;

Future<void> loadUser() async {
  setState(() {
    isLoading = true;
  });

  final result = await repository.getUser();

  setState(() {
    user = result;
    isLoading = false;
  });
}
```

There was nothing wrong with this approach. It was simple and easy to understand. But as the application grew, I started having more state and business logic inside my widgets. That's when I started looking into BLoC.

## What is BLoC?

BLoC stands for **Business Logic Component**. The main idea is to move the business logic out of the widget and let the UI focus on displaying the state.

For example, instead of calling `loadUser()` directly from the widget, I can send an event to the BLoC. The BLoC extends the `Bloc` class and takes `UserEvent` and `UserState` as its types. I can then listen for `LoadUser` and handle the user-loading logic inside the BLoC.

The flow is basically:

```text
UI
 ↓
LoadUser
 ↓
UserBloc
 ↓
UserLoading
 ↓
UserLoaded / UserError
```

```dart
class UserBloc extends Bloc<UserEvent, UserState> {
  final UserRepository repository;

  UserBloc(this.repository) : super(UserInitial()) {
    on<LoadUser>((event, emit) async {
      emit(UserLoading());

      try {
        final user = await repository.getUser();
        emit(UserLoaded(user));
      } catch (e) {
        emit(UserError(e.toString()));
      }
    });
  }
}
```

Once the BLoC is handling the user loading, the UI can listen to the state and display the appropriate content.

```dart
BlocBuilder<UserBloc, UserState>(
  builder: (context, state) {
    if (state is UserLoading) {
      return const CircularProgressIndicator();
    }

    if (state is UserLoaded) {
      return Text(state.user.name);
    }

    if (state is UserError) {
      return Text(state.message);
    }

    return const SizedBox();
  },
)
```

And when the user wants to load the data, we just send the event:

```dart
ElevatedButton(
  onPressed: () {
    context.read<UserBloc>().add(LoadUser());
  },
  child: const Text('Load User'),
)
```

## Conclusion

BLoC is a state management solution, but what I like about it is the separation between the UI and the business logic. It's not always necessary, but when the logic starts growing, it can make a big difference.
